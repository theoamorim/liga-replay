# Liga Replay — Fase 0 + 1 (MVP) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Site público da liga + painel admin + súmula do mesário, com classificação e estatísticas recalculadas automaticamente, publicado em `ligareplay.web.app`.

**Architecture:** Monorepo com `web/` (SPA React) e `functions/` (Cloud Functions). Regras de negócio puras (classificação, desempate, qualificação, tabela, estatísticas) ficam em `functions/src/domain/` e são testadas sem Firebase; as Functions só leem o Firestore, chamam o domínio e gravam documentos calculados. O site lê documentos prontos. Desenvolvimento 100% no Firebase Emulator Suite com projeto `demo-liga-replay`.

**Tech Stack:** Node 20, TypeScript, React 18 + Vite + React Router + Tailwind CSS, Firebase JS SDK v10+, firebase-functions v5 (v2 API; v1 só para trigger de criação de usuário), firebase-admin, Vitest, @testing-library/react, @firebase/rules-unit-testing, Playwright (smoke).

**Spec:** `docs/superpowers/specs/2026-10-23-liga-replay-design.md`

## Global Constraints

- Todo texto de interface em português do Brasil.
- Tema escuro; tokens: fundo `#0E0E10`, superfície `#17171A`, borda `#2A2A2E`, texto `#EDE6DD`, texto suave `#A39E96`, cobre `#B87333`, bronze claro `#D4A373`. Títulos em Playfair Display, corpo em Inter (Google Fonts).
- Mobile first: layout funciona a partir de 360px de largura, sem rolagem horizontal; alvos de toque ≥ 44px.
- Firestore em `southamerica-east1`. Regras negam por padrão.
- Pontos padrão: vitória 3, empate 1, derrota 0.
- Desempate (grupo): pontos → confronto direto (mini-tabela por pontos entre os empatados) → saldo de gols → gols pró → menos gols sofridos → sorteio.
- Ranking entre grupos (3º e 4º): mesma ordem sem confronto direto.
- Formato `padrao-12-times`: 1º e 2º de cada grupo diretos; melhor 3º direto; outros dois 3º + dois melhores 4º na repescagem; pior 4º eliminado.
- Gol contra conta para o adversário e não conta como gol do jogador. Pênaltis de desempate não contam em estatística nem no placar.
- Só jogos com `status == "encerrado"` entram em classificação e estatísticas.
- Telefone, documento e data de nascimento só em `players/{id}/private/dados`; documento exibido mascarado (`***.***.123-**`).
- Papéis em custom claims: `admin: boolean`, `mesario: boolean`, `capitaoDe: string[]`.

## Review Focus

1. Mesário reabre/corrige uma súmula já encerrada → estatísticas recalculadas sem contar em dobro (recalcular duas vezes dá o mesmo resultado). Teste em Task 6.
2. Evento lançado errado e apagado → placar e estatísticas diminuem. Teste em Task 4 e Task 6.
3. Três times empatados em pontos e todos empataram entre si → confronto direto não resolve e cai para saldo de gols. Teste em Task 2.
4. Grupo com jogos ainda não disputados → classificação parcial considera só encerrados e times sem jogo aparecem com zeros. Teste em Task 2.
5. Mesário tentando lançar evento em jogo de outro campo/mesário ou em jogo encerrado → negado pelas regras. Teste em Task 7.

### Task 2: Classificação e desempate

**Files:**
- Create: `functions/src/domain/types.ts`, `functions/src/domain/standings.ts`
- Test: `functions/src/domain/standings.test.ts`

**Interfaces:**
- Produces (`types.ts`):
  ```ts
  type MatchStatus = "agendado" | "ao-vivo" | "encerrado";
  type Fase = "grupos" | "repescagem-semi" | "repescagem-final" | "quartas" | "semi" | "final";
  interface MatchResult { id: string; fase: Fase; grupo?: string; rodada: number;
    mandanteId: string; visitanteId: string; golsMandante: number; golsVisitante: number; status: MatchStatus; }
  interface PointsConfig { vitoria: number; empate: number; derrota: number; }
  interface StandingRow { teamId: string; grupo: string; posicao: number;
    j: number; v: number; e: number; d: number; gp: number; gc: number; sg: number; pts: number; }
  ```
- Produces (`standings.ts`): `computeGroupStandings(grupo: string, teamIds: string[], matches: MatchResult[], pts: PointsConfig, rng?: () => number): StandingRow[]` (ordenado, `posicao` 1..n) e `compareOverall(a: StandingRow, b: StandingRow): number` (sem confronto direto; usado na Task 3).

- [ ] **Step 1:** Testes:
  - `vitória 3, empate 1`: A 2x1 B, C 0x0 D → A pts 3, B 0, C 1, D 1.
  - `ignora não encerrados`: jogo `agendado` 5x0 não altera nada; times sem jogos aparecem com zeros (Review Focus 4).
  - `confronto direto antes do saldo`: A e B com 6 pts, A tem SG menor mas venceu B → A em 1º.
  - `três empatados com confronto direto empatado`: A, B, C com mesmos pts e todos 1x1 entre si → ordem por saldo de gols (Review Focus 3).
  - `gols sofridos`: empate em pts, confronto, SG e GP → menos GC fica à frente.
  - `sorteio`: tudo igual → usa `rng` (com `rng = () => 0` resultado determinístico).
- [ ] **Step 2:** `npm test -w functions -- standings` → FAIL.
- [ ] **Step 3:** Implementar. Algoritmo do confronto direto: agrupar por `pts`; para cada grupo empatado com ≥2 times, montar mini-tabela só com jogos entre eles e ordenar por pontos dessa mini-tabela; subgrupos ainda empatados seguem SG → GP → menor GC → sorteio (não reaplicar confronto recursivamente).
- [ ] **Step 4:** PASS.
- [ ] **Step 5:** Commit `feat: classificação com critérios de desempate`.
